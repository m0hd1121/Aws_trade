# API Reference

Base URL: `http://<host>:8000`. All responses are JSON. Interactive docs
are auto-generated by FastAPI at `/docs` (Swagger) and `/redoc`.

## Bot control — `/api/bot`

| Method | Path | Effect |
|---|---|---|
| POST | `/start` | Start Bot — builds/starts the `BotRunner` for the configured mode |
| POST | `/stop` | Stop Bot — stops the polling loop |
| POST | `/pause` | Pause — polling loop idles, no new decisions |
| POST | `/resume` | Resume from pause |
| POST | `/restart` | Restart — full stop + rebuild + start |
| POST | `/reset-session` | Reset Session — clears in-memory KZ/day progress only; trade history is untouched |
| POST | `/emergency-stop` | Emergency Stop — flattens every open position, cancels every pending order, halts the day |
| POST | `/refresh` | Manual Refresh — returns the current status snapshot |
| GET | `/status` | Current `BotState` + full runner snapshot |
| POST | `/broker-connect` | Broker Connection panel — set/update MT5 credentials live, no `.env` edit or restart |

`POST /broker-connect` body (all fields optional; only supplied ones
change):

```json
{
  "login": 12345678,
  "password": "your-password",
  "server": "YourBroker-Demo",
  "bridge_mode": "local",
  "bridge_host": "127.0.0.1",
  "bridge_port": 8001,
  "persist": true
}
```

Returns `{"success": bool, "live": bool, "message": "..."}` — `live:
true` means it reconnected an already-running bot in place; `live:
false` means the bot wasn't running yet, so this was a connectivity test
against the settings (which are still saved either way). `persist: true`
(default) also writes the changed fields to `.env` so they survive a
restart. Login/logout happens purely through the MT5 API's own
`initialize()`/`login()` calls — no terminal GUI is opened or scripted,
in either `bridge_mode`.

All control endpoints return the same shape as `GET /status`:

```json
{
  "state": "RUNNING",
  "config_mode": "PAPER",
  "runner": {
    "mode": "PAPER",
    "paused": false,
    "stopped": false,
    "emergency": false,
    "account": { "equity_current": 10123.45, "daily_realized_loss_percent": 0.0, "...": "..." },
    "instruments": {
      "EURUSD": { "stage": "WAITING_FOR_SWEEP", "active_trade": null, "pending_trade": null, "...": "..." }
    }
  }
}
```

Invalid transitions (e.g. `/pause` while `STOPPED`) return `409` with the
reason in `detail`.

## Dashboard reads — `/api/dashboard`

| Path | Returns |
|---|---|
| `GET /status` | Same as `/api/bot/status` |
| `GET /account` | Live broker account info (equity/balance/margin), if connected |
| `GET /positions` | Open positions from the execution adapter |
| `GET /trades/open` | Open/pending trades from the DB |
| `GET /trades/closed?limit=` | Closed trades, most recent first |
| `GET /trades/skips?limit=` | Scored skips (setups that didn't clear the bar) |
| `GET /performance` | Win rate, avg winner/loser R, expectancy, compliance rate vs. Section 12 |
| `GET /equity-curve?limit=` | Cumulative-R series + running drawdown, for the chart |
| `GET /execution-log?limit=` | Strategy stage transitions (the transparency panel) |
| `GET /system-logs?limit=` | Structured application logs |
| `GET /connection-health` | Latest status per monitored component (feed, broker adapter) |
| `GET /ai-insights?limit=` | Analytics-only output — never a strategy input |

## Configuration — `/api/config`

| Method | Path | Effect |
|---|---|---|
| GET | `/` | Current operational config (config.yaml contents) |
| PUT | `/` | Replace operational config — body `{"config": {...}}`. Strategy rule numbers are not part of this object and cannot be changed here. |
| GET | `/strategy-rules` | Read-only view of the frozen strategy constants, for dashboard transparency |

## WebSocket — `/api/ws`

Connect and receive a push every ~2s:

```json
{ "type": "status", "data": { "...": "same shape as GET /api/bot/status" } }
```

No client → server messages are required; the endpoint just needs the
socket kept open (send anything to keep it alive if your client requires
periodic traffic).

## Auth

Optional HTTP Basic Auth, off by default. Set both `DASHBOARD_USERNAME`
and `DASHBOARD_PASSWORD` (in `.env`) to require it across the entire app —
static dashboard files, every `/api/*` route, and the `/api/ws`
WebSocket alike (`/api/healthz` stays exempt for uptime checks). Leave
both blank to run open, e.g. behind your own VPN/SSH tunnel/reverse
proxy. Strongly recommended once you start entering real broker
credentials through the Broker Connection panel — see
`api/auth.py`/`docs/DEPLOYMENT.md`.
